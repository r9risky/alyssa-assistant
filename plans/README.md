# Implementation Plans

Plans 005-027 were added on 2026-08-13 after a standard-depth audit of the full
source tree, with deeper coverage of security, audio/interruption, background
watchers, plugins, Windows behavior, packaging, and product direction.

This is an extracted source tree with no `.git` directory. Every plan therefore
uses a current-state excerpt drift check instead of a commit SHA. If these plans
are copied into a git checkout, executors should create the branch named in the
plan and compare all in-scope files against the excerpts before changing them.

Status values: **TODO**, **IN PROGRESS**, **DONE**, **BLOCKED** (with reason), or
**REJECTED** (with rationale). Execute in the order below unless dependency notes
explicitly permit parallel work. Read each plan fully and honor its STOP conditions.

## Dependency notes and safe parallelism

- **Immediate security lane**: 005 and 006 can execute in parallel. Then run
  007 -> 008 -> 009 -> 012. Plan 011 follows 005.
- **Independent quick fix**: 010 can execute immediately in parallel with the
  security lane. Plan 027 can follow 005 and plan 026 can follow 013.
- **Test/concurrency lane**: 013 establishes deterministic fakes. Then 014 -> 015
  -> 016. Plan 017 follows 015; plan 018 follows 017. These are ordered because
  audio and watcher concurrency changes are unsafe without the preceding state
  contracts and tests.
- **Documentation**: 019 follows landed security/behavior changes so it documents
  reality once, rather than repeatedly drifting during implementation.
- **Packaging**: 020 precedes 021 because optional profiles must use the reviewed
  constraints and Python support matrix.
- **Architecture**: 022 waits for protected secret storage, runtime tests, and
  stable plugin reload boundaries before extracting services from `overlay.py`.
- **Direction**: 023-025 are design/spike plans. They must not enable production
  defaults until their recorded review verdict is approved.
- 026 and 027 are small contained bug plans and may execute as soon as their
  stated dependencies land even though their numbers follow the direction plans.

- The removed/always-approve voice-ID behavior was reported as both correctness
  and security; it is one plan, 007.
- NumPy truthiness, premature listener-result reads, overlapping capture, and
  interrupted pipelined-TTS cleanup share one interruption lifecycle and are
  combined in plan 014.
- Timer interval clamping is part of watcher scheduling and is included in 017.
- Malformed nested plugin metadata, stale watcher snapshots, stale sibling
  imports, and non-atomic schemas/functions are combined in 018.
- Camera disconnect state and Calendar credential discovery were named as
  lower-priority audit findings and receive plans 026 and 027.

## Findings considered and rejected

- **Optimize memory matching**: rejected. Storage is deliberately bounded to a
  small configured list, so algorithmic optimization has negligible payoff.
- **Replace the watcher system with asyncio**: rejected. Bounded workers plus the
  existing thread/coordinator model address demonstrated blocking without an
  application-wide concurrency migration.
- **Delete `token_compression.py` outright**: rejected. The stub preserves caller
  compatibility; plan 019 corrects the false documentation.
- **Refactor `brain.py`, `actions.py`, and `overlay.py` together**: rejected. The
  combined blast radius is excessive; plan 022 extracts the clearest services
  only after tests and boundaries exist.
- **Immediately migrate to `pyproject.toml`**: rejected. Plans 020-021 solve the
  demonstrated reproducibility/profile problems while preserving the project's
  Windows unzip-and-run model.
- **Treat arbitrary local plugin execution as a standalone vulnerability**:
  rejected as by design. Plan 006 removes the dangerous elevated context, while
  plan 025 explicitly states manifests are not a Python sandbox.
- **Treat configured cloud screen vision as an undisclosed leak**: rejected.
  Screen capture is user-triggered and provider-dependent; documentation must
  remain accurate, but no implementation-specific unauthorized transfer was found.
- **Report dependency CVEs without evidence**: rejected. `pip-audit` was absent,
  and no high/critical reachable advisory was established from local evidence.

## Audit coverage and limits

The standard pass read root configuration and launch/build scripts, all key core
modules, the full audio/transcription path, plugin loader, all shipped plugins,
tests, README, existing plans, and security-sensitive GUI settings code. It did
not run a live microphone, camera, cloud provider, Google OAuth flow, GPU
transcription, scheduled task installation, or PyInstaller build. Git churn and
history could not be assessed because the source archive contains no `.git` data.
